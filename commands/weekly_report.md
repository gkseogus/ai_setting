이번 주 노션 일지를 토대로 대표 보고용 주간 업무 보고서를 만들어 PDF 로 저장한다.

## 인자
$ARGUMENTS — 모두 선택사항. 자유 텍스트로 받는다.
- **출력 경로/파일명**: 예) `~/Desktop/reports`, `~/Desktop/2026-W30_주간보고.pdf`. 비어 있으면 `~/Desktop/주간업무보고서_YYYY-MM-DD_MM-DD.pdf` 로 저장한다 (시작일은 연도 포함 `YYYY-MM-DD`, 종료일은 연도 없이 `MM-DD`. 예: `주간업무보고서_2026-07-20_07-24.pdf`).
- **대상 주**: 예) `2026-W30`, 또는 그 주에 속한 날짜 `2026-07-20`. 비어 있으면 오늘이 속한 주로 잡는다.
- **작성자**: 예) `작성자: 홍길동`. 비어 있으면 헤더의 작성자 칸을 비워 둔다.
- 예시: `~/Desktop/reports 2026-W30 작성자: 홍길동`

## 어디에 쓰는가
대표에게 올리는 **주간 업무 보고서**를 만든다. 근거 데이터는 사용자의 노션 일지 트리다.
```
일지
└── YYYY-MM (예: 2026-07)
    └── YYYY-MM-DD (예: 2026-07-21)  ← /notion_diary 로 쌓인 일 단위 작업 묶음
```
이번 주(월~금)에 해당하는 날짜 페이지들을 모아 읽고, 아래 5개 섹션으로 재구성해 PDF 로 뽑는다. 일지를 **읽기만** 하고 고치지 않는다.

## 주간 범위 (월~금 고정)
- 기본은 **오늘이 속한 주의 월요일 ~ 금요일** (KST). 주말(토·일)은 범위에서 제외한다.
- 인자로 `YYYY-Www` 또는 특정 날짜가 오면 그 날짜가 속한 주의 월~금으로 대체한다.
- 계산 방법(KST):
  - 오늘 요일을 구한다: `date +%u` (월=1 … 일=7).
  - 이번 주 월요일 = 오늘 − (요일−1) 일, 금요일 = 월요일 + 4 일.
  - 예: `date -v-mon '+%Y-%m-%d'`(월요일), `date -v-mon -v+4d '+%Y-%m-%d'`(금요일) 로 확인.
- 헤더에는 "월~금" 기간을 그대로 표기하되, 필요하면 그 주에 실제 일지가 있는 날만 근거로 삼는다.

## 보고서 양식 (반드시 이 5개 섹션 순서 그대로)

문서 상단 헤더:
```
주간 업무 보고
기간: YYYY-MM-DD(월) ~ YYYY-MM-DD(금)  (YYYY년 N주차)
작성자: <있으면 표기, 없으면 빈칸>
작성일: YYYY-MM-DD
```

본문 섹션:
```
1. 이번 주 진행 업무
   - <프로젝트명> — <이번 주에 무엇을 진행했는지 한 줄. 활동/경과 중심>
   - ...

2. 완료 업무 (결론)
   - <프로젝트명> — <무엇이 끝났고, 그래서 무엇이 달라졌는지(결론). 결과 중심>
   - ...

3. 지연 중이거나 확인이 필요한 업무
   - <항목> — <왜 지연/대기 상태인지, 무엇이 막고 있는지>
   - ...

4. 다음 주 예정 업무
   - <항목> — <다음 주에 할 일. 이번 주 미결/후속 작업에서 도출>
   - ...

5. 대표 확인/결정이 필요한 사항
   - <항목> — <무엇을, 왜 대표가 결정해야 하는지. 선택지가 있으면 함께>
   - ...
```

### 섹션별 채우는 규칙
- **1. 이번 주 진행 업무**: 이번 주 일지에서 손댄 프로젝트/작업을 **활동 관점**으로 묶는다. 프로젝트 단위로 한 줄씩. "무엇을 하고 있었는가".
- **2. 완료 업무 (결론)**: 일지에서 `- [x]` 로 마무리된 묶음을 **결과 관점**으로 정리한다. "그래서 무엇이 달라졌다/해결됐다"가 드러나게. 1번과 중복되는 프로젝트라도 여기서는 결론만 적는다.
- **3. 지연/확인 필요**: 일지에 `TODO(root-cause)`, "대기", "블로커", "확인 필요", "미해결", "보류", "이슈" 같은 신호가 있거나, 목적 대비 완결되지 않은 항목을 뽑는다.
- **4. 다음 주 예정**: 일지의 후속 작업 언급·미결 항목에서 도출한다. 명시된 게 없으면 3번의 미결 항목을 다음 주 할 일로 옮겨 적는다.
- **5. 대표 확인/결정**: 비용/계약/정책/방향성 등 **사용자 권한 밖의 의사결정**이 필요한 것만. 일지에 근거가 있으면 그대로, 애매하면 3번에서 대표 판단이 필요한 것만 승격시킨다.
- **근거 없는 항목은 지어내지 않는다.** 일지에서 도출할 수 없으면 해당 섹션에 `- (해당 없음)` 을 넣거나, 4·5번이 비면 작성 직전에 사용자에게 "다음 주 예정/대표 결정 사항 추가할 것 있는지" 한 번 물어본다.

## 말투 규칙
- **평어 / 개조식 고정** — 명사형·개조식으로 끊어 쓴다. 예: "자동 퇴근 워커 정상화 완료", "결제 연동 테스트 잔여 3건 진행 중", "인프라 비용 승인 필요".
- 존댓말·음슴체 쓰지 않는다. 각 항목은 짧은 구/절로.
- **비개발자(대표)도 이해할 수 있게** — 기술 용어 최소화, 어쩔 수 없으면 괄호로 짧게 풀어준다. 예: "cron(정해진 시각에 자동 실행되는 작업)".
- **결과·의사결정 중심** — 코드가 어떻게 바뀌었는지가 아니라, 사업/운영 관점에서 무엇이 달라졌고 무엇을 정해야 하는지로 적는다.
- **이모지 금지.**
- 사용자가 인자/대화에서 다른 말투를 명시하면 그 지시를 우선한다. 기본값만 평어·개조식.

## 데이터 수집 순서
1. 오늘 날짜와 이번 주 월~금을 구한다(위 "주간 범위" 방식, KST).
2. 노션에서 `일지` 페이지를 찾는다. `notion-search` 로 "일지" 검색 → `notion-fetch` 로 트리를 내려간다.
3. 이번 주에 걸치는 `YYYY-MM` 페이지(들)를 열고, 그 아래 **월~금 각 날짜 페이지**를 `notion-fetch` 로 읽는다. (주가 두 달에 걸치면 두 `YYYY-MM` 페이지를 모두 본다.)
4. 각 날짜 페이지의 작업 묶음(프로젝트명 — 요약 / 목적 / 추가사항 / 수정사항 / 그 외)을 파싱해 **프로젝트별로 합친다.**
5. 합친 내용을 위 5개 섹션 규칙에 따라 분류한다. PR/이슈 링크가 있으면 완료 업무 항목 끝에 짧게 단다.
6. 이번 주 일지가 하나도 없으면 그 사실을 사용자에게 알리고, git 로그로 대체할지 아니면 사용자가 직접 불러줄지 물어본 뒤 진행한다. (없는 내용을 지어내 채우지 않는다.)

## 보고서 디자인 (Re:B Studios 템플릿 고정)
- 디자인은 **고정 템플릿**을 쓴다: `~/Desktop/ai_setting/template/weekly_report_template.html` (브라운/크림 톤 Re:B Studios 양식).
  - 이 파일을 복제해 `{{PLACEHOLDER}}` 와 `<!-- REPEAT ... -->` 블록만 이번 주 데이터로 채운다. `<style>` 는 절대 바꾸지 않는다.
  - 템플릿 파일이 없으면 최소 대체 스타일(아래 "권장 스타일")로 만들되, 있으면 반드시 템플릿을 우선한다.
- 구성 요소:
  - **상단**: 브랜드 라벨(`RE:B STUDIOS · WEEKLY REPORT`) → 대형 타이틀 `주간 업무 보고서` → 기간(월~금) → `작성자 | 기준 | 작성일` → 두꺼운 다크 브라운 바.
  - **KPI 카드 5개**: 일지에서 **실제로 도출 가능한 수치만** 넣는다. 기본 조합 = 진행 프로젝트 수 / 완료 세부작업 수(`- [x]` 묶음 개수) / 관련 PR 수 / 핵심 비즈니스 지표(비용 절감·인프라 자원 등) / 대표 결정 대기 수. 근거 없는 수치는 만들지 않는다.
  - **섹션 1~5**: 위 5개 섹션과 1:1. 1번은 `①②③` 항목 + 날짜 뱃지, 2·4번은 `▪` 불릿(끝에 회색 PR/이슈 메타), 3번은 좌측 상태 태그 테이블(`p-wait/p-set/p-next/p-clean/p-check`), 5번은 원형 번호 + 좌측 액센트 카드.
  - **푸터**: `Re:B Studios · YYYY년 M월 N주차 주간 업무 보고서 | 데이터 출처: ...` (중앙 정렬).
- 권장 스타일(대체용): `@page { size: A4; margin: 16mm 15mm; }`, 본문 `font-family: -apple-system, "Apple SD Gothic Neo", "Pretendard", "Malgun Gothic", sans-serif;`, 인쇄 색 보존 `print-color-adjust: exact;`.

## PDF 생성 순서
1. 위 디자인 템플릿을 복제해 **HTML 파일**로 만든다. 임시 경로: `<출력 pdf 경로와 같은 폴더>/.<파일명>.html` 또는 `mktemp`. 채운 뒤 `{{`·`REPEAT` 흔적이 남지 않았는지 확인한다.
2. 출력 경로를 정한다. 인자에 경로가 있으면 그것(디렉토리면 그 안에 기본 파일명), 없으면 `~/Desktop/주간업무보고서_YYYY-MM-DD_MM-DD.pdf` (시작일 연도 포함, 종료일 `MM-DD`). 상위 폴더가 없으면 `mkdir -p`.
3. HTML → PDF 변환. 아래 순서로 사용 가능한 첫 번째 방법을 쓴다:
   - **(A) Chromium 계열 headless 인쇄 (1순위).** 아래 후보 중 존재하는 첫 바이너리로 실행:
     ```
     후보:
       "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
       "/Applications/Chromium.app/Contents/MacOS/Chromium"
       "/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge"
       "/Applications/Brave Browser.app/Contents/MacOS/Brave Browser"
       ~/Library/Caches/ms-playwright/chromium-*/chrome-mac/Chromium.app/Contents/MacOS/Chromium
     실행:
       "<바이너리>" --headless=new --disable-gpu --no-pdf-header-footer \
         --print-to-pdf="<출력.pdf>" "file://<HTML 절대경로>"
     ```
     (`--no-pdf-header-footer` 가 먹지 않는 구버전이면 빼고 재시도.)
   - **(B) Playwright MCP (2순위).** A 가 전부 없으면 `browser_navigate` 로 `file://<HTML>` 열고 `browser_run_code_unsafe` 로 `await page.pdf({ path: "<출력.pdf>", format: "A4", printBackground: true })` 실행. (headless 모드에서만 동작하므로 A 를 우선한다.)
   - **(C) 폴백.** 둘 다 실패하면 PDF 를 만들지 못했음을 알리고, 생성한 **HTML 파일 경로**를 그대로 안내한다(브라우저에서 열어 "PDF 로 저장" 하면 됨). 임의로 성공했다고 보고하지 않는다.
4. PDF 가 실제로 생성됐는지 확인한다: 파일이 존재하고 크기가 0 이 아닌지 (`ls -la`, `file <출력.pdf>` 로 `PDF document` 인지). 확인되면 임시 HTML 은 지운다(문제 시 남겨서 디버깅).
5. 사용자에게 저장된 **PDF 절대경로**를 알려주고, 5개 섹션 각각 몇 줄로 채워졌는지 짧게 요약한다. `open "<출력.pdf>"` 로 열지 여부는 사용자가 원하면 실행한다(기본은 열지 않음).

## 주의사항
- **노션은 읽기 전용.** 일지 페이지를 수정/삭제/덮어쓰지 않는다.
- **자동 commit / push 금지.** 이 커맨드는 git 을 만지지 않는다.
- **없는 내용 지어내기 금지.** 특히 4·5번 섹션은 일지 근거가 없으면 비워 두거나 사용자에게 확인한다. 미검증 추측을 대표 보고서에 넣지 않는다.
- **결과가 실제로 나왔는지 검증하고 보고한다.** PDF 파일 존재·타입을 확인하기 전에는 "생성 완료" 라고 하지 않는다. 폴백(C)로 빠졌으면 그 사실과 HTML 경로를 그대로 알린다.
- 항목이 너무 많으면 섹션당 핵심 5~8줄로 압축한다. 사소한 리팩토링·오타 수정은 묶어서 한 줄.
- 대상 주가 두 달(예: 월요일이 6월, 금요일이 7월)에 걸치면 `YYYY-MM` 페이지 두 개를 모두 확인한다.
