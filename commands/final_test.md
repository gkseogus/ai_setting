## 운영 안전 규칙 (모든 단계에 우선)

- **기본은 읽기 전용**: 운영에는 `GET` / `HEAD` 요청, 페이지 조회, 클릭으로 인한 화면 이동만 허용한다.
- `POST` / `PUT` / `PATCH` / `DELETE`, 폼 제출, 결제, 메일·알림 발송, 데이터 생성은 **항목별로 사용자 동의**를 받은 뒤에만 실행한다. 동의 시에도 테스트 계정 / 테스트 데이터로만 수행하고 끝나면 정리 여부를 보고한다.
- 부하·반복 호출 금지: 같은 엔드포인트는 최대 3회, 요청 간 간격을 둔다. 부하 테스트는 이 커맨드 범위가 아니다.
- 실제 사용자 계정·개인정보 사용 금지. 로그인이 필요하면 사용자에게 테스트 계정을 요청한다.
- 토큰·쿠키·키는 출력/로그/스크린샷에 남기지 않는다 (마스킹).
- 이 커맨드는 **판정만** 한다. 실패를 발견해도 운영 코드를 즉석 수정·재배포하지 않는다.

### 3. 회귀 테스트
1. **자동화 스위트 (로컬/CI)** — 배포 커밋과 같은 커밋에서 실행:
   - 백엔드: `pytest -q`
   - 프론트: `npx vitest run`
   - 결과가 이미 CI 에 있으면 `gh run list --commit <sha>` / `gh run view` 로 확인하고 재실행은 생략해도 된다.
2. **E2E 를 운영에 붙이는 경우**: `tests/e2e/**` 중 읽기 전용 spec 만 골라 `BASE_URL=<운영 URL> npx playwright test <spec>`. 쓰기가 섞인 spec 은 실행하지 않고 목록만 보고.
3. **변경 기능 수동 회귀 (운영, Playwright)**: 1단계 회귀 대상 각각에 대해 사용자 관점 흐름(진입 → 조회 → 필터/페이지네이션 → 상세)을 따라가며 기대 결과를 확인한다. 이전 동작과 비교가 필요하면 `git show <since>:<파일>` 로 이전 로직을 근거로 기대값을 정한다.

### 4. 판정
- 모든 항목을 `PASS` / `FAIL` / `SKIP(사유)` 로 기록한다. "대충 됨"은 없다.
- **FAIL 이 하나라도 있으면**:
  - 재현 조건(URL, 요청, 응답 코드/본문 요약, 스크린샷)을 정리한다.
  - 심각도 분류: `P0` 서비스 불가·데이터/보안/결제 영향 → 롤백 권고 / `P1` 핵심 기능 오동작 → 핫픽스 권고 / `P2` 부분·시각 이슈 → 후속 티켓.
  - 원인 분석이 필요하면 `/root_cause` 로 넘긴다 (이 커맨드 안에서 수정하지 않는다).
- `SKIP` 은 실패가 아니지만 보고에 반드시 사유를 남긴다 (예: 쓰기 동작 미승인, 테스트 계정 없음).

## 금지 사항
- 실행하지 않은 항목을 PASS 로 적는 것. 근거 칸이 빈 PASS 는 무효.
- "아마 괜찮을 것" 같은 미검증 판정.
- 동의 없이 운영에 쓰기 요청을 보내거나 부하를 주는 것.
- 빌드·lint·타입체크 통과만으로 회귀 PASS 처리하는 것.
- FAIL 을 발견하고 이 커맨드 안에서 운영 코드를 수정·재배포하는 것.
