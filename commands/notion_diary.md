현재 세션에서 작업한 내용을 노션 일지에 음슴체로 비개발자도 볼 수 있게 정리한다.

## 인자
$ARGUMENTS — 정리 대상 범위 (선택사항). 비어 있으면 현재 세션에서 작업한 변경점을 자동 분석.

## 어디에 쓰는가
사용자의 노션 워크스페이스에는 다음 구조의 일지 트리가 있다.
```
일지
└── YYYY-MM (예: 2026-05)
    └── YYYY-MM-DD (예: 2026-05-15)  ← 이 페이지에 작업 묶음을 토글로 추가
```
오늘 한 일을 위 구조의 오늘 날짜 페이지에 추가한다. 오늘 날짜 페이지가 없으면 새로 만들고, 있으면 본문 끝에 이어 붙인다.

## 작성 양식 (반드시 이 구조 그대로)

```
- [x] **<프로젝트명> — <한 줄 요약 제목>**
- **목적**
    - <왜 했는지. 어떤 문제가 있었고 이번 작업으로 무엇이 바뀌는지>
- **추가사항**
    - **<항목명>** — <비개발자도 이해할 수 있는 동작 설명>
- **수정사항**
    - **<항목명>** — <어떤 문제를 어떻게 고쳤는지>
- **그 외**
    - <테스트, 리팩토링, 문서 등 부수 작업>
    - PR: [<org>/<repo>#<번호>](<PR 링크>) (있을 때만)
```

- 한 세션에서 두 가지 이상의 묶음을 했으면 묶음마다 위 블록을 통째로 반복한다.
- "추가사항", "수정사항", "그 외" 중 해당 없는 항목은 생략한다.
- "목적"은 반드시 포함한다.

## 말투 규칙
- **음슴체 고정** — "추가함", "고침", "정상화함", "분리함", "갱신함" 등 `~함/~음` 어미.
- **비개발자도 이해할 수 있게** — 기술 용어 최소화. 어쩔 수 없이 쓰면 괄호로 짧게 풀어준다. 예: "MCP(외부 서비스를 Claude 에 붙이는 통로)", "cron(정해진 시각에 자동으로 도는 작업)".
- **결과 중심으로** — "어떤 코드가 어떻게 바뀌었다" 가 아니라 "사용자/관리자 입장에서 무엇이 달라졌다" 로 적는다.
- **이모지 금지** — 사용자가 명시적으로 요청한 경우(예: Slack 알림에 들어가는 🗑️) 만 예외.

## 작업 순서

1. 오늘 날짜를 구한다 (`date +%Y-%m-%d`, KST 기준).
2. 노션에서 `일지` 페이지를 찾고, 그 아래 `YYYY-MM` 페이지 → 그 아래 `YYYY-MM-DD` 페이지를 차례로 확인한다.
   - `notion-search` 로 "일지" 검색 → `notion-fetch` 로 트리 따라 내려간다.
   - `YYYY-MM` 페이지가 없으면 `일지` 아래에 새로 만든다.
   - `YYYY-MM-DD` 페이지가 없으면 `YYYY-MM` 아래에 새로 만든다.
3. 현재 세션에서 작업한 내용을 모은다.
   - `git log --pretty=format:'%h | %ad | %s' --date=short -30` 으로 최근 커밋 확인.
   - 사용자가 인자로 범위를 지정했으면 그 범위만, 비어 있으면 "직전 일지 작성 이후 새로 추가된 커밋" 을 대상으로 한다.
   - 커밋 메시지를 의미 단위로 묶는다 (예: 같은 주제의 연속 커밋은 한 블록으로).
4. 위 양식대로 음슴체 / 비개발자용 문장으로 풀어 쓴다.
   - 묶음마다 PR 이 있으면 `gh pr list` 또는 사용자 입력에서 PR 번호를 받아 링크를 단다.
   - PR 이 없으면 "그 외" 마지막 줄에 레포 링크 (`[org/repo](https://github.com/org/repo)`) 만 단다.
5. 결과 블록을 `YYYY-MM-DD` 페이지 본문 끝에 추가한다.
   - 이미 페이지에 내용이 있으면 그 뒤에 빈 줄 두 개를 두고 이어 붙인다.
6. 작성이 끝나면 사용자에게 페이지 URL 을 알려준다.

## 주의사항
- 자동 commit 금지 — 사용자가 명시적으로 요청하지 않는 한, 이 커맨드는 git 에 아무 것도 커밋/푸시하지 않는다.
- 노션 페이지를 통째로 덮어쓰지 않는다. 기존 내용은 보존하고 끝에 이어 붙이기만 한다.
- 한 묶음에 너무 많은 항목을 넣지 않는다. 5~7 줄 안에서 핵심만 잡힌다. 사소한 리팩토링은 "그 외" 한 줄로 처리.
- 사용자가 음슴체가 아닌 말투(존댓말, 평어 등) 를 명시적으로 지시했으면 그 지시를 따른다. 기본값만 음슴체.

## 예시 (참고용, 출력은 동일 구조로)

```
- [x] **Re:B Attendance — 자동 퇴근 워커 정상화 + 17:00 KST 기록 + 프론트엔드 컨벤션 정돈**
- **목적**
    - 매일 1회 동작해야 할 자동 퇴근 워커가 cron 스케줄 강등과 시간 가드 조합 때문에 단 한 번도 실제 퇴근 레코드를 남기지 못하던 상태였음. 이를 정상화하고, 회사 정책에 맞춰 자동 퇴근으로 기록되는 시각을 17:00 KST 로 고정한다
- **추가사항**
    - 자동 퇴근 워커가 매일 한국시간 자정 직후 1회 안정적으로 발사되도록 cron 스케줄을 매일 1회 (KST 00:00 = UTC 15:00) 로 고정함
- **수정사항**
    - 기존 cron 은 매 30분 호출 스케줄로 작성돼 있었으나 Vercel Hobby 플랜이 일 1회로 자동 강등시켜 임의 시각 1회만 호출되고 있었음. 스케줄·가드·날짜 계산을 함께 보정해 정상화함
- **그 외**
    - 자동화 테스트 17건 신규 추가 (전체 e2e 206 → 223건)
    - PR: [ReB-studios/reb_attendance#23](https://github.com/ReB-studios/reb_attendance/pull/23)
```
