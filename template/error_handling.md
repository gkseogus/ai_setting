# Error Handling — 표면 vs 근본 판단

모든 에러 / 버그 / 예외 / 실패한 동작을 다룰 때 아래 5단계를 반드시 따른다.
"에러 메시지만 보고 try/except 또는 if 가드로 우회"는 수정이 아니다.

---

## 1단계 — Triage (분류): "뿌리를 뽑을까, 싹만 자를까"

코드를 고치기 전, 사용자에게 명시적으로 둘 중 하나를 한 줄로 보고하고 동의를 받는다.

### 근본 처리 (뿌리 뽑기) — 다음 중 하나라도 해당하면 무조건 근본 처리
- 데이터 손상 / 보안 / 결제 / 인증 / 권한 관련
- 같은 코드 패턴이 다른 파일·모듈에도 존재해서 재발 가능
- 증상이 여러 원인 중 하나에 의해 발생할 수 있는 상황
- 우회만 하면 사일런트 실패(에러는 안 나지만 결과가 틀림) 위험
- 근본 원인을 모르는데 "고쳐졌다"고 보고하려는 충동이 들 때

### 표면 처리 (싹 자르기) — 다음 모두 해당할 때만 허용
- 영향 범위가 명확히 국소적이고 1회성
- 근본 수정 비용이 매우 크고 영향이 작음
- 임시 핸들링이 명시적이고 추적 가능 (코드에 `# TODO(root-cause): <사유>`)
- 사용자가 표면 처리를 명시적으로 요청 / 동의

판단 결과를 사용자에게 1~2문장으로 보여주고 동의를 받은 뒤 다음 단계로 넘어간다.

---

## 2단계 — Root Cause Tracing (근본 처리로 결정된 경우)

증상이 아닌 원인을 찾는다. 다음을 모두 수행한다.

1. **재현**: 에러를 정확히 재현하는 최소 조건을 확인. 재현 불가면 그 사실과 가설을 명시.
2. **5 Whys**: "왜 발생했나" → "그건 왜?" → 최소 5번 파고든다. 각 Why마다 코드 / 로그 / DB / 네트워크 응답 등 증거를 첨부.
3. **호출 / 데이터 흐름 추적**: 스택 트레이스, 호출 그래프, DB 상태로 **트리거(증상이 드러난 지점)와 진짜 원인(증상을 만든 지점)을 분리**.
4. **유사 패턴 검색**: 같은 코드 패턴 / 같은 실수가 다른 파일·모듈에도 있는지 grep / ast-grep으로 후보를 리스트업.
5. **가설 vs 증거 분리**: "이게 원인일 것이다"는 가설일 뿐. "X파일 Y라인에서 Z 조건일 때 W가 발생함을 로그/테스트로 확인했다"로 결론 짓는다.

---

## 3단계 — Fix (수정)

- **근본 처리**: 원인 지점을 직접 고친다. 회피 / 우회 / 방어 코드만 추가하는 것은 금지.
- **표면 처리**: 어디서 어떻게 임시 처리했는지 코드에 `# TODO(root-cause): <원인 가설 + 후속 작업>` 형태로 남긴다.
- 2단계에서 찾은 **유사 패턴**도 함께 수정한다. "그건 다른 이슈"라며 미루지 않는다.

---

## 4단계 — Verification (검증)

다음 4개를 모두 수행한 뒤에만 "끝났다"고 보고한다. 하나라도 빠지면 미완료.

1. **증상 재현 불가 확인**: 원래 에러를 재현시키던 조건을 실제로 실행해 더 이상 발생하지 않음을 확인 (curl / 스크립트 / 브라우저 클릭 / 테스트 명령).
2. **유사 패턴 확인**: 2단계 4번에서 찾은 같은 패턴들에서도 같은 증상이 없는지 확인.
3. **회귀 확인**: 원래 잘 되던 정상 흐름이 깨지지 않는지 최소 1개 이상 직접 동작 / 테스트로 확인.
4. **재발 방지 테스트**: 자동화 가능한 경우 같은 에러를 잡는 테스트를 추가한다.

타입체크 / 빌드 / lint 가 통과하는 것만으로는 검증이 아니다. **실제 동작을 관찰**해야 한다.

---

## 5단계 — Report (보고)

수정 완료 후 사용자에게 아래 5개 항목을 그대로 출력한다.

- **처리 방식**: 근본 / 표면
- **근본 원인**: 한 문장 요약 (증거 기반)
- **수정 범위**: `파일:라인` + 변경 요지, 함께 수정한 유사 패턴
- **검증 방법**: 실제로 실행한 명령 / 동작과 그 결과
- **잔여 리스크 / 후속 작업**: 있으면 명시, 없으면 "없음"

---

## 금지 사항

- "고친 것 같습니다" / "아마 될 것입니다" 같은 **미검증 보고**.
- 검증 4단계 중 하나라도 빠뜨린 채 "끝났다" 보고.
- 에러 메시지만 보고 `try/except`, `if` 가드로 우회하면서 그것을 "수정"이라 칭하는 것.
- 표면 처리하면서 사용자에게 그 사실을 알리지 않는 것.
- 근본 원인을 모르는 채로 "재시작하면 됩니다" / "다시 해보세요" 식으로 넘기는 것.
